# Optional media in lead-reading

`ReadingMedia` is generated alongside the existing Markdown response, never by a second model call. Zero aids is a normal response. The three-aid cap is a ceiling, not a quota. Paper/article prompts retain their original interpretation and cropped-PDF page mapping; tutoring keeps its existing plain-text protocol.

Lecture variants carry their own media. Generic reading messages carry `readingMedia`; source text, citations, learning progress and previous messages are not rewritten. A variant without media must not inherit another version's aids. The complete explanation remains in Markdown for history, export and understanding extraction.

Each aid is anchored to a paragraph ending of the same response using presentation-normalized matching (Markdown emphasis, whitespace, line breaks and full-width punctuation). Ambiguous or missing anchors keep a valid aid in a labelled appendix instead of guessing a paragraph or losing the diagram. Invalid structures and out-of-range PDF pages carry a persisted unavailable marker, rendered as a notice without an extra generation attempt. Explicit dangling diagram introductions before a new section or the end receive an inline notice; existing text chains and tables remain unchanged. Previously discarded diagram data cannot be reconstructed from prose and is never invented. Flow, parallel branches, feedback cycles, part hierarchies and small comparison tables are distinct representations, all fully expanded. Terms reuse the local bilingual definition popover.

Source figures use the original PDF page, not generated images or model-provided URLs. Only the chosen pages render as they approach the viewport; shared document handles are released after consumers unmount. Page images are memory-only and do not enter saved chats. Preview failure retains explanatory prose and the original-page link. Enlarging is optional; it is not a gate to the explanation.

Verification: readingAids.test.tsx, skimExplanation.test.ts, skimTakeaways.test.ts and services/readingMedia.test.ts cover optional/invalid media, scope, same-call generation, variant persistence, source mapping and unchanged non-reading callers. Browser checks must use React.StrictMode and include actual PDF page rendering, enlargement, term popovers, mobile/container layout and switching back to prose-only content. No paid API is needed for these checks.
