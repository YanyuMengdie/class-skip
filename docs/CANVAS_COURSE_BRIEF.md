# Canvas 课程简报（本地试用）

入口：资料库首页的「本周课程简报」，或侧栏「课程与日历 → 本周课程」。原有个人日历仍在「我的日历」。

## 使用

1. 沿用 Canvas 导入功能中的学校地址与个人 Access Token，验证当前 Canvas 身份。
2. 选择 1–12 门课程、周次和显示时区。
3. 点击「同步并生成本周简报」。首次读取多门课程可能需要几分钟，可以取消。
4. 周报默认分三部分：「这周上什么，读什么」「本周任务与截止时间」「大作业，提前准备」。每项先呈现整理后的中文摘要、关键要求和准备建议；完整说明、逐字引用与来源折叠保留。已提交或豁免的本周任务收在「本周已完成」。
5. 大作业区筛选下周起两周内、单项占总成绩至少 10% 的作业或考试。本周截止的同类任务仍在本周任务区，并标明占比。未来的其他小任务、无周次资料和一般课程规则默认折叠。

这是手动读取的快照。关闭页面后不会自动同步，不会代交作业或修改 Canvas 内容。

## 内容与证据

- 先从安排来源确认本周具体 Lecture 与 Reading。阅读文章和非本周普通教学材料只保留名称与链接，不读正文。只有确切对应本周特定讲次的 PDF 才另行读取，生成 1–2 句介绍、最多 3 个核心概念与轻量预习建议。
- 本周课件导读单独核对 PDF 页原文；课件正文不进入课程安排提取，不用于创造任务或截止日期。对应关系含糊、课件未开放、文章链接或文字无法可靠提取时保留安排，说明未生成导读的原因。
- 读取当前账户可访问的 syllabus、课程日程、公告、模块安排、课程日历，以及作业/测验/讨论要求。只跟进明确的安排页面；首页也可用于定位被隐藏目录挡住的本课大纲和日程链接。
- 附件先按用途筛选：仅大纲、日程/阅读清单、明确的考试/作业说明等安排 PDF 读取正文并保留原始页码。普通 lecture outline、练习卷、往年考试和用途不清的资料只保留目录；教师明确标注为大纲的数字文件名可被识别。
- 全学期结构化截止日期保留。本周及后两周的任务说明优先分析；无日期或 Canvas 标记缺交的任务仍核对。过去发布但影响当前安排的公告保留，上传日期不用于推断授课周次。
- 重复同步先核对文件元数据；同身份、同范围且更新时间未变的安排 PDF 复用已完整读取的正文。课程来源、任务状态、周次、时区和学期上下文均未变且上次审核完整时，复用 AI 核对结果；更新或失败会重新核对。
- Canvas `due_at` 使用当前账户返回的日期；开放时间和入口关闭时间不会冒充截止时间。Calendar 同时读取课程事件和当前账户的作业截止；按作业 ID 合并日历与作业列表，保留提交状态。日期矛盾时保留一项任务及两份依据并显示冲突。
- Astra 分批提取安排，再进行一次独立语义核对。代码检查同课来源、逐字引用、明确的日期格式、必做/选做依据和关联作业。
- 月日缺少年份时，仅在 Canvas 明确的本课学期起止范围内恰有一个可能日期才补齐，并展示依据。没有这一依据时不猜年份。具体时刻缺少时区时保留已知日期，单独说明时间尚未确定。
- 明确的日历周范围可形成「本周安排」，不伪造某天授课。只写 Week N 而没有明确日历映射时，不按开学日自行数周。
- 未对应周次的 Lecture/Reading 折叠存放；成绩构成、一般规则、缺考等条件说明单独收纳。真实日期冲突仍提示；文字日期无法解析不会自动把有效 Canvas 日期标成冲突。
- 只有通过关联审核的同一作业截止信息会与 API 截止时间比较。阅读安排、上课时间不会被当作作业延期。
- 安排核对后再进行中文摘要编辑和独立核对。保留限时、次数、不可返回、字数、提交方式、教师禁止使用 AI 等关键要求，不直接展示整段英文说明，也不靠截断长文充当摘要。核对失败不展示旧摘要，原始说明仍可展开。
- 准备建议与教师要求分开，基于真实任务或本周课件内容，不创造新任务。
- 从 syllabus Evaluation 和同课明确的评分说明中核对单项占比。比例须有逐字原文及独立审核；不将「所有小测共 20%」套给某一次小测，不推算缺失占比，不按 Canvas 原始分值猜总成绩权重。冲突或不明确时不作为已确认大作业。
- “已提交”来自实际提交记录或明确的提交状态。仅有成绩不代表已提交；要求重交时另行提示。

## 失败与范围

- 代理只允许同校只读 API。分页中断不会作为完整列表返回。
- 同步失败保留之前的简报。部分来源或 AI 整理失败会显示缺口，旧的相关安排会保留为待重新核对，不凭空消失。
- 旧任务本次未返回会记录变化，但不会直接称为“取消”。
- 只读到目录的其他课件会独立列出，不自动认定为本周必读。正常按范围跳过 Lecture/Reading 正文不计为读取缺口。
- 外部文章只保留链接；外部大纲、日程、任务说明，以及非 PDF 安排附件、扫描页或无权限安排资料未能核对时，仍明确显示缺口。
- 不访问未选课程。公告从已知课程/学期起点查询到当天；起点不明确时回看所选周之前 370 天并提示。课程日历读取所选周前一周至后两周。
- 为避免无限读取，当前每课最多 80 个模块、30 个相关安排页面及独立首页、30 份安排附件；PDF 最大 25 MB。先筛选再计入附件上限，普通课件不挤占大纲的位置。文字总量和 AI 批次也有上限，达到上限会记录缺口。
- 特定讲次导读每次最多读取 12 份本周 PDF，每份不超过 25 MB、140 页和 8 万字。无法完整读取时说明原因，不截去后半本后宣称已完整整理。文章正文始终不读。
- Astra 额度/频率限制等整理失败单独说明，和 Canvas 来源无权限、任务日期冲突分开呈现；不会把模型生成失败说成课程安排本身不明确。
- AI 引用校验和二次审核能减少编造，仍不等于保证安排完整或教师原始材料无误。每项保留可查原文与同步时间。

## 保存与连接

- Canvas 令牌仅在当前浏览器会话保存；服务器转发不会向外部下载域名携带令牌。
- 简报保存在当前浏览器，按应用账户隔离，最近三份持久保存；展示前核对 Canvas 学校与用户 ID。
- 旧版简报保留并提示重新同步。新摘要缓存要求同身份、同周次、同来源全文与同任务状态；未更新的本周导读也会先重新核对文件元数据和访问权限。旧的 Lecture/文章全文不会用于安排提取缓存。
- 更换应用/Canvas 账户清空当前展示，迟到的同步响应不会覆盖另一个账户。
- 本功能使用既有本地 Astra 服务端配置，不依赖新增 Firebase 数据结构。只在手动生成时发起 AI 请求。

主要文件：`features/canvas/brief/`、`services/canvas.ts`、`server/canvasProxy.ts`、`shared/layout/DashboardScreen.tsx`。

测试覆盖代理分页/下载安全、日期解析、账号隔离、原文审核、取消、旧信息保留、测验去重和界面分组。自动测试使用模拟数据，没有连接真实课程或消耗真实 AI 额度。
